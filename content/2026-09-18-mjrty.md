In an election with many candidates,
what is the most efficient way to find the candidate, if any, who
has received a majority (more than half[^majority]) of the votes?

Boyer and Moore's [MJRTY algorithm](https://en.wikipedia.org/wiki/Boyer%E2%80%93Moore_majority_vote_algorithm)
uses constant space and works in at most two passes over the collection of votes.
More remarkably, alongside their implementation in Fortran, they developed a
mechanized proof of correctness using a verification system for Fortran, in 1980!

To quote their later paper[^paper] (1991):

> We still think of this as a minor landmark in the development of formal
> verification and automated reasoning: here for the first time a new algorithm
> is presented along with its mechanilcally checked correctness proof—eleven years
> after the work.

Wouldn't it be fun to verify a Fortran program in Creusot,
a verification system for Rust?

# The MJRTY algorithm

The algorithm works as follows:

1. The first pass finds a single candidate who is the one with the majority
   of votes if a majority exists.
2. The second pass checks whether that candidate has the majority of votes.
   This pass can be skipped if a majority is known to exist in advance.

The first pass is the interesting part of the solution.
The idea is to group votes into pairs of votes for different candidates.
If a majority exists, there must remain unpaired votes only for the
majority candidate. With some trickery, we can refine this idea into
a constant-space algorithm.

Loop over the votes using only a counter `K` and a "current candidate"
`CAND`. For each vote, if it is a vote for `CAND` then increment `K`.
Otherwise, decrement `K`. If `K` reaches zero, the candidate
of the next vote becomes `CAND`, and we reset `K` to 1.

Intuitively, `K` represents a set of unpaired votes for the "current candidate"
`CAND`, we increment `K` when we accumulate more unpaired votes, we decrement
it when we find a pairing, and when we run out of unpaired votes, the next
vote will be unpaired and its candidate becomes the new "current candidate" `CAND`.

# MJRTY in Fortran

```fortran
      SUBROUTINE MJRTY(A, N, BOOLE, CAND)
      INTEGER N
      INTEGER A
      LOGICAL BOOLE
      INTEGER CAND
      INTEGER I
      INTEGER K
      DIMENSION A(N)
      K = 0
C     THE FOLLOWING DO IMPLEMENTS THE PAIRING PHASE. CAND IS THE CURRENT
C     LY LEADING CANDIDATE AND K IS THE NUMBER OF UNPAIRED VOTES FOR CAN
C     D. 
      DO 100 I = 1, N
      IF ((K .EQ. 0)) GOTO 50
      IF ((CAND .EQ. A(I))) GOTO 75
      K = (K - 1)
      GOTO 100
50    CAND = A(I)
      K = 1
      GOTO 100
75    K = (K + 1)
100   CONTINUE
      IF ((K .EQ. 0)) GOTO 300
      BOOLE = .TRUE.
      IF ((K .GT. (N / 2))) RETURN
C     WE NOW ENTER THE COUNTING PHASE. BOOLE IS SET TO TRUE IN ANTICIPAT
C     ION OF FINDING CAND IN THE MAJORITY. K IS USED AS THE RUNNING TALL
C     Y FOR CAND. WE EXIT AS SOON AS K EXCEEDS N/2. 
      K = 0
      DO 200 I = 1, N
      IF ((CAND .NE. A(I))) GOTO 200
      K = (K + 1)
      IF ((K .GT. (N / 2))) RETURN
200   CONTINUE
300   BOOLE = .FALSE.
      RETURN
      END
```

Fortran programs used to be stored on punch cards.
The language bears visible traces of its history:

- each line is one instruction (no need for semicolons);
- the first five columns of each line are reserved for labels
  (a number, used by `GOTO` jumps) or the character `C` indicating a comment;
- lowercase hadn't been discovered yet. 😛

The program above begins with a bunch of variable declarations,
followed by common imperative instructions:

- assignments, `K = 0`;
- for loops, `DO 100 I = 1, N`, where `100` is the label of the `CONTINUE` that
  ends the loop body, don't ask me why;
- conditional instructions, `IF`;
- jumps, `GOTO 50`, `RETURN`, `CONTINUE`.

To prove a Fortran program correct using Creusot, the first step
is to rewrite it in Rust.

# MJRTY in Rust

```rust
fortran! {
        K = 0
        DO I = 1, N
        IF ((K .EQ. 0)) GOTO 'L50
        IF ((CAND .EQ. A(I))) GOTO 'L75
        K = (K - 1)
        GOTO 'L100
'L50    CAND = A(I)
        K = 1
        GOTO 'L100
'L75    K = (K + 1)
'L100   CONTINUE
        IF ((K .EQ. 0)) GOTO 'L300
        BOOLE = .TRUE.
        IF ((K .GT. (N / 2))) RETURN
        K = 0
        DO I = 1, N
        IF ((CAND .NE. A(I))) GOTO 'L200
        K = (K + 1)
        IF ((K .GT. (N / 2))) RETURN
'L200   CONTINUE
'L300   BOOLE = .FALSE.
        RETURN
        END
}
```

The `fortran!` macro compiles a minimal subset of Fortran into Rust.
It's written as a declarative macro (`macro_rules!`),
which is more fun to write than a procedural macro
at the expense of a couple of syntactic restrictions:

- `GOTO` labels use lifetime syntax (in real Fortran they are arbitrary strings of maximum length 5);
- Rust's declarative macros are insensitive to whitespace, so we must rely on other contextual information to delimit instructions. Luckily, the syntax of instructions turns out to be self-delimiting (at least for the subset that we see here).

We wrap this snippet of code in a Rust function that declares all of
the relevant variables, and repackages the result into a more modern format, `Option`.
And we make it polymorphic because we can.

```rust
#[allow(non_snake_case)]
pub fn mjrty<T: Eq>(A: &[T]) -> Option<&T> {
    let N = A.len();
    let mut BOOLE: bool;
    let mut CAND: Option<&T> = None;
    let mut K: usize;
    let mut I: usize;

    fortran! {
                K = 0
                DO I = 1, N
                IF ((K .EQ. 0)) GOTO 'L50
                IF ((CAND .EQ. A(I))) GOTO 'L75
                K = (K - 1)
                GOTO 'L100
        'L50    CAND = A(I)
                K = 1
                GOTO 'L100
        'L75    K = (K + 1)
        'L100   CONTINUE
                IF ((K .EQ. 0)) GOTO 'L300
                BOOLE = .TRUE.
                IF ((K .GT. (N / 2))) RETURN
                K = 0
                DO I = 1, N
                IF ((CAND .NE. A(I))) GOTO 'L200
                K = (K + 1)
                IF ((K .GT. (N / 2))) RETURN
        'L200   CONTINUE
        'L300   BOOLE = .FALSE.
                RETURN
                END
    }

    if BOOLE { CAND } else { None }
}
```

# Proving MJRTY correct, step by step

Here is a laundry list of everything we must do to verify the `mjrty` function.

## Add `T: DeepModel` constraint

```rust
pub fn mjrty<T: Eq + DeepModel>(A: &[T]) -> Option<&T> { /* ... */ }
```

At first, Creusot won't even compile this function (even though `rustc` will).
In our ambitiousness, we made it polymorphic, parameterized by `T: Eq`.
But to reason about equality comparisons (`IF ((CAND .EQ. A(I)))`),
Creusot needs a *model of equality*.

The specification of `Eq` is that its method `eq` must implement an equivalence relation.
Another way to define this concept is that every element of type `T` has a *model*,
so that `eq` evaluates to `true` if and only if its two operands have the same model.
This model is provided by the trait `DeepModel`.

Hence Creusot requires a `DeepModel` constraint whenever `Eq` is used.

In spite of the name of this trait and its method, I will stick to saying that
`x.deep_model()` is the "equality model" of `x` in English.

In Creusot, `==` actually has two meanings depending on the context.
Within a Rust program it has the meaning you expect: it desugars to
calling the `eq` method of `Eq`. But in the specification language Pearlite,
it refers to a primitive notion of equality. In logic, the fact `x == y`
really means that `x` and `y` are completely identical, and you can freely
substitute one for the other.

To illustrate this distinction, we can say:
in Rust, `x == y` evaluates to `true` if and only if,
in logic, `x.deep_model() == y.deep_model()`.

If you find this confusing, rest assured that for basic types like integers
and booleans, these notions of equality coincide. So you can pretend that
`T` is `usize` for example and ignore anything that has to do with this distinction.

In any case, in the remainder of this post,
we will always use `==` with its logic meaning.

## Postcondition

The postcondition is most important part in this contract.

```rust
#[ensures(match result {
    Some(cand) => count(A, 1, A@.len()+1, *cand) > A@.len() / 2,
    None => forall<x> count(A, 1, A@.len()+1, x) <= A@.len() / 2,
})]
```

If the result is `Some(cand)` for some candidate `cand`, then
that candidate must have the majority of votes.
We define a logic function `count` to count the votes of a given candidate
`x` in a slice. There are subtly different ways to define this function.

```rust
/// Number of votes for `x` in `v` between indices `i` and `j` (`j` excluded).
/// `i` will always be set to 1 in this post.
#[logic(open)]
#[requires(1 <= i && i <= j && j <= v@.len() + 1)]
#[variant(j)]
pub fn count<T: DeepModel>(v: &[T], i: Int, j: Int, x: T) -> Int {
    pearlite! {
        count_(v, i, j, x.deep_model())
    }
}
```

The first detail to note is that we start by extracting `x.deep_model()`,
that is the equality model of `x`, before recursing in the auxiliary function
`count_`. Indeed, since we use `Eq` to compare candidates, we consider
`x` and `y` to be the same candidate if their equality models,
`x.deep_model()` and `y.deep_model()`, are identical.

This approach to defining `count` gives us the following fact for free.
It will be useful in the correctness proof.

**Fact 1:** if `x.deep_model() == y.deep_model()`, then `count(v, i, j, x) == count(v, i, j, y)`.

With a different definition of `count`, we would have had to prove that fact
explicitly.

Then comes the recursive function `count_`. Logic functions must terminate,
and here termination is justified because the argument `j` decreases
at every recursive call, as indicated by `#[variant(j)]`,
and it is positive, as we can deduce from the precondition `#[requires(...)]`.

The function `count_` recurses by decrementing `j` rather than by incrementing `i`,
again to make verification easier.

Note also that Fortran arrays are 1-indexed, whereas Rust slices are 0-indexed.
The function `count_` receives 1-indexed indices `i` and `j`, and
uses 0-indexed indexing in its body (`v@[j-2]`). We index `v@` at `j-2`,
subtracting one to shift 1-indexing into 0-indexing, and subtracting one again
because we are counting elements up to `j` excluded.

```rust
#[logic(open)]
#[requires(1 <= i && i <= j && j <= v@.len() + 1)]
#[variant(j)]
pub fn count_<T: DeepModel>(v: &[T], i: Int, j: Int, x: T::DeepModelTy) -> Int {
    pearlite! {
        if j <= i {
            0
        } else if v@[j-2].deep_model() == x {
            1 + count_(v, i, j - 1, x)
        } else {
            count_(v, i, j - 1, x)
        }
    }
}
```

# MJRTY proved correct in Creusot

```rust
#[allow(non_snake_case)]
#[requires(A@.len() < usize::MAX@)]
#[ensures(match result {
    None => forall<x> count(A, 1, A@.len()+1, x) <= A@.len() / 2,
    Some(cand) => count(A, 1, A@.len()+1, *cand) > A@.len() / 2,
})]
pub fn mjrty<T: Eq + DeepModel>(A: &[T]) -> Option<&T> {
    let N = A.len();
    let mut BOOLE: bool;
    let mut CAND: Option<&T> = None;
    let mut K: usize;
    let mut I: usize;

    snapshot! { count_monotonic::<T> };

    fortran! {
                K = 0
                #[invariant(1 <= I@ && 0 <= K@ && K@ < I@ && I@ <= N@ + 1)]
                #[invariant(match CAND {
                    None => I@ == 1,
                    Some(cand) =>
                        K@ <= count(A, 1, I@, *cand) && count(A, 1, I@, *cand) <= K@ + (I@ - 1 - K@) / 2
                        && forall<x: T> x.deep_model() != cand.deep_model() ==> count(A, 1, I@, x) <= (I@ - 1 - K@) / 2,
                })]
                DO I = 1, N
                IF ((K .EQ. 0)) GOTO 'L50
                IF ((CAND .EQ. A(I))) GOTO 'L75
                K = (K - 1)
                GOTO 'L100
        'L50    CAND = A(I)
                K = 1
                GOTO 'L100
        'L75    K = (K + 1)
        'L100   CONTINUE
                IF ((K .EQ. 0)) GOTO 'L300
                BOOLE = .TRUE.
                IF ((K .GT. (N / 2))) RETURN
                K = 0
                #[invariant(1 <= I@ && I@ <= N@ + 1)]
                #[invariant(K@ <= N@ / 2)]
                #[invariant(exists<cand> CAND == Some(cand)
                    && K@ == count(A, 1, I@, *cand)
                )]
                DO I = 1, N
                IF ((CAND .NE. A(I))) GOTO 'L200
                K = (K + 1)
                IF ((K .GT. (N / 2))) RETURN
        'L200   CONTINUE
        'L300   BOOLE = .FALSE.
                RETURN
                END
    }

    // Hint for the `RETURN` of the second loop.
    proof_assert! { forall<x, i> 1 <= i && i <= N@ && x == A@[i-1]
        ==> count(A, 1, i, x) + 1 == count(A, 1, i+1, x) }

    if BOOLE { CAND } else { None }
}
```
